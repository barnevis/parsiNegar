# معماری پارسی‌نگار

## ۱. هدف

پارسی‌نگار یک ویرایشگر Markdown مبتنی بر **معماری بنیان** و **چارچوب Pey** است که توسعهٔ آن به‌صورت تدریجی انجام می‌شود.

نسخهٔ نخست تنها یک صفحهٔ ساده برای نوشتن و ویرایش Markdown است و قابلیت‌های پیشرفته در مراحل بعدی افزوده می‌شوند.

## ۲. اجزای اصلی

پارسی‌نگار از اجزای زیر استفاده می‌کند:

* **Pey:** چارچوب اجرای برنامه و مدیریت افزونه‌ها.
* **افزونه‌های Pey:** قابلیت‌های عمومی مورد نیاز برنامه که به‌صورت بسته‌های مستقل نصب می‌شوند.
* **pey-webui:** چارچوب رابط کاربری پارسی‌نگار.
* **CodeMirror:** کتابخانهٔ ویرایش متن که درون لایهٔ UI و توسط کامپوننت‌های پارسی‌نگار استفاده می‌شود.
* **Parsneshan:** کتابخانهٔ مستقل پردازش Markdown که در صورت نیاز از طریق افزونهٔ مناسب در محیط Pey استفاده می‌شود.
* **افزونه‌های پارسی‌نگار:** قابلیت‌های اختصاصی برنامه که در صورت نیاز در خود پروژه پیاده‌سازی می‌شوند.

CodeMirror بخشی از معماری مستقل برنامه نیست و نباید به‌عنوان لایه‌ای موازی با Pey در نظر گرفته شود؛ جایگاه آن در **لایهٔ UI** است.

## ۳. ساختار کلی

```text
پارسی‌نگار
│
├── Runtime Host
│   └── src/app/
│
├── Pey
│   ├── هسته
│   └── افزونه‌های Pey
│
├── UI
│   └── pey-webui
│       │
│       └── کامپوننت‌های پارسی‌نگار
│           │
│           └── CodeMirror
│
├── Parsneshan
│
└── افزونه‌های پارسی‌نگار
    └── src/plugins/
```

Pey و افزونه‌های آن وابستگی‌های پروژه هستند و کد آن‌ها در مخزن پارسی‌نگار قرار نمی‌گیرد.

## ۴. ساختار پوشه‌ها

ساختار پروژه به شکل زیر است:

```text
parsinegar/
├── src/
│   ├── app/
│   │   └── ...
│   │
│   ├── ui/
│   │   ├── components/
│   │   │   └── editor/
│   │   │       └── ...
│   │   └── ...
│   │
│   └── plugins/
│       └── ...
│
├── tests/
│   └── ...
│
├── docs/
│   └── ...
│
├── public/
│   └── ...
│
├── bootstrap.json
├── index.html
├── package.json
├── README.md
├── LICENSE
└── .gitignore
```

`node_modules/` در مخزن پروژه قرار نمی‌گیرد و باید در `.gitignore` تعریف شود.

### `src/app/`

`src/app/` نقش **Runtime Host** را ایفا می‌کند.

این بخش مسئول آماده‌سازی محیط اجرای برنامه، ایجاد `ConfigSource`، `EnvSource` و `ModuleLoader` و در نهایت فراخوانی `core.start()` است.

```text
src/app/
│
├── ConfigSource
├── EnvSource
├── ModuleLoader
│
└── core.start()
```

`src/app/` محل پیاده‌سازی هستهٔ Pey نیست؛ Runtime Host برنامه است که محیط لازم را برای اجرای هسته فراهم می‌کند.

### `src/ui/`

کد رابط کاربری پارسی‌نگار در این بخش قرار می‌گیرد.

`pey-webui` برای ساخت رابط کاربری استفاده می‌شود و CodeMirror درون کامپوننت ویرایشگر مصرف می‌شود.

```text
src/ui/
└── components/
    └── editor/
        └── ...
             │
             └── CodeMirror
```

### `src/plugins/`

این بخش فقط برای افزونه‌های اختصاصی پارسی‌نگار است.

افزونه‌های Pey در این پوشه قرار نمی‌گیرند و به‌صورت بسته‌های مستقل نصب می‌شوند.

اگر یک قابلیت پارسی‌نگار در آینده مشخص شود که عمومی و قابل استفاده در سایر پروژه‌های Pey است، می‌تواند از پروژه جدا شده و به یک افزونهٔ مستقل Pey تبدیل شود.

### `tests/`

آزمون‌های پروژه در این بخش قرار می‌گیرند.

### `docs/`

مستندات اختصاصی پارسی‌نگار در این بخش قرار می‌گیرند.

### `public/`

فایل‌های ایستای عمومی پروژه در این بخش قرار می‌گیرند.

### `bootstrap.json`

`bootstrap.json` فایل الزامی راه‌اندازی پروژه است و در ریشهٔ پروژه قرار می‌گیرد.

این فایل تنها محل تعریف **Adapterها، Pluginها و مسیر UI** است و توسط Runtime Host در فرایند راه‌اندازی برنامه مورد استفاده قرار می‌گیرد.

## ۵. رابط کاربری

نسخهٔ نخست تنها شامل یک صفحهٔ ساده و یک محیط نوشتن Markdown است.

در این مرحله موارد زیر جزو محدودهٔ پروژه نیستند:

* نوار ابزار
* پنل‌های جانبی
* مدیریت تم
* پیش‌نمایش جداگانه
* تنظیمات
* مدیریت پیشرفتهٔ فایل
* قابلیت‌های پیشرفتهٔ ویرایش

این قابلیت‌ها در صورت ایجاد نیاز واقعی و در مراحل بعدی افزوده خواهند شد.

## ۶. نقش Parsneshan

Parsneshan یک کتابخانهٔ مستقل است و نباید به Pey یا پارسی‌نگار وابسته شود.

در صورت نیاز، Parsneshan می‌تواند از طریق یک افزونه در محیط Pey مورد استفاده قرار گیرد.

```text
Parsneshan
    │
    └── افزونهٔ Pey
            │
            └── پارسی‌نگار
```

پارسی‌نگار نباید کد Parsneshan را در سورس خود کپی کند.

## ۷. نقش CodeMirror

CodeMirror مسئول قابلیت‌های مربوط به ویرایش متن است و درون کامپوننت‌های UI پارسی‌نگار استفاده می‌شود.

CodeMirror یک لایهٔ مستقل در معماری برنامه نیست و نباید در کنار Pey یا pey-webui به‌عنوان یک بخش هم‌سطح قرار گیرد.

در صورت نیاز به سازگار کردن یک زیرساخت خارجی با معماری Pey، از **Adapter** استفاده می‌شود؛ ایجاد Adapter برای اجزایی که نیازی به آن ندارند ضروری نیست.

## ۸. افزونه‌ها

معماری پارسی‌نگار بر پایهٔ سیستم افزونهٔ Pey است.

افزونه‌ها به دو گروه تقسیم می‌شوند:

1. **افزونه‌های Pey:** افزونه‌های عمومی اکوسیستم Pey که به‌صورت بستهٔ مستقل نصب می‌شوند.
2. **افزونه‌های پارسی‌نگار:** افزونه‌هایی که صرفاً برای نیازهای پارسی‌نگار ایجاد شده‌اند و در `src/plugins/` قرار می‌گیرند.

در صورتی که یک افزونهٔ اختصاصی پارسی‌نگار قابلیت عمومی پیدا کند، می‌تواند به‌صورت یک پروژهٔ مستقل در اکوسیستم Pey منتشر شود.

بنابراین پروژه دارای لایهٔ جداگانه‌ای با نام `features/` نیست؛ قابلیت‌های توسعه‌پذیر در قالب افزونه پیاده‌سازی می‌شوند.

## ۹. راه‌اندازی برنامه

راه‌اندازی پارسی‌نگار از طریق Runtime Host انجام می‌شود:

```text
bootstrap.json
      │
      ▼
src/app/
      │
      ├── ConfigSource
      ├── EnvSource
      └── ModuleLoader
              │
              ▼
         core.start()
              │
              ▼
             Pey
              │
       ┌──────┴──────┐
       ▼             ▼
    Plugins          UI
                       │
                  pey-webui
                       │
                    Editor
                       │
                  CodeMirror
```

این ساختار باعث می‌شود مسئولیت راه‌اندازی، اجرای چارچوب، رابط کاربری و ویرایش متن از یکدیگر جدا باقی بمانند.

## ۱۰. توسعهٔ تدریجی

توسعهٔ پارسی‌نگار از یک ویرایشگر بسیار ساده آغاز می‌شود و قابلیت‌ها بر اساس نیاز واقعی افزوده می‌شوند:

```text
صفحهٔ ساده
    ↓
ویرایش Markdown
    ↓
پردازش Markdown با Parsneshan
    ↓
قابلیت‌های بیشتر ویرایش
    ↓
Live Preview
    ↓
مدیریت اسناد و سایر قابلیت‌ها
```

معماری پروژه نباید پیش از ایجاد نیاز واقعی، برای قابلیت‌های آینده پیچیدگی ایجاد کند.

## ۱۱. اصول کلیدی

> **پارسی‌نگار باید از یک ویرایشگر ساده آغاز شود و به‌تدریج به یک ویرایشگر پیشرفته تبدیل شود؛ نه اینکه از ابتدا با معماری و قابلیت‌های یک محصول کامل ساخته شود.**

> **Pey و افزونه‌های آن وابستگی‌های پروژه‌اند و سورس آن‌ها در پارسی‌نگار قرار نمی‌گیرد.**

> **CodeMirror بخشی از لایهٔ UI است، نه یک لایهٔ مستقل در کنار Pey.**

> **قابلیت‌های توسعه‌پذیر پارسی‌نگار در قالب افزونه پیاده‌سازی می‌شوند و لایهٔ مستقلی با نام `features/` وجود ندارد.**

> **قابلیت عمومی باید در اکوسیستم Pey قابل استفاده باشد و قابلیت اختصاصی باید در پارسی‌نگار باقی بماند.**
